# リポジトリ整理ルール

## 背景
過去にリポジトリ直下へ資料ファイル（移行用zip、技術選定検討資料docx等）や重複したスキーマファイルが紛れ込んだことがある。再発防止のためのルール。

## 守ること
- スキーマファイルの正本は `db/schema.sql` のみ。ルート直下やその他の場所に `schema.sql` を複製・放置しない
  - 現状ルート直下に未追跡の `schema.sql` が残っている場合、`db/schema.sql` との差分を確認し、必要な内容だけ `db/schema.sql` に反映してから削除する（無断で削除しない。差分の扱いは人に確認する）
- 提案書・検討資料・移行手順などのドキュメント類は `docs/`（`.gitignore`対象）に置き、アプリのソースコードと混在させない
- `node_modules/`・`.wrangler/`・`.dev.vars` は `.gitignore` 済み。新しいビルド成果物・一時ファイルが増えた場合は都度追記する

## 新しいファイルを作るとき
- 追加するファイルがアプリの実行に必要なコードか、ドキュメント・一時ファイルかを判断する
- ドキュメント・一時ファイルであれば `docs/` に置き、リポジトリ直下を汚さない
